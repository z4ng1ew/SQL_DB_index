## 1. Что такое индекс B-дерева (BTree)?

**BTree** = **B**alanced **Tree** = сбалансированное дерево

Представь **телефонный справочник** (бумажный):

**Без индекса** (красная линия):
```
Иванов Пётр ... тел. 123
Смирнов Иван ... тел. 456
Петров Сергей ... тел. 789
... (ещё 1000 страниц)
Яковлев Андрей ... тел. 999
```
Чтобы найти "Яковлева", нужно просмотреть **все страницы** с начала до конца. Это **последовательное сканирование** (Sequential Scan).

**С индексом B-дерева** (зелёная линия):
```
Справочник разделён на разделы:
А-Д (страницы 1-250)
Е-К (страницы 251-500)
Л-П (страницы 501-750)
Р-Я (страницы 751-1000)
```
Ты сразу открываешь раздел "Р-Я" → внутри него подраздел "Я" → находишь "Яковлева".

**B-дерево** — это такая структура данных, которая организует информацию как **дерево с ветками**:
- Корень (верхний уровень) → делит данные на большие куски
- Ветки (средние уровни) → делят на меньшие куски
- Листья (нижний уровень) → содержат сами данные

## 3. Что такое "логарифмическая сложность"?

**Логарифм простыми словами** = "сколько раз нужно разделить число пополам, чтобы получить 1"

Примеры:
```
ln(8) ≈ 3, потому что:
8 → 4 → 2 → 1 (3 шага)

ln(1000000) ≈ 14, потому что:
1000000 → 500000 → 250000 → ... → 1 (примерно 14 шагов)
```

**В программировании** это как **бинарный поиск** (binary search):
```javascript
// Линейный поиск O(n) - красная линия
function findLinear(arr, target) {
    for (let i = 0; i < arr.length; i++) {  // Проверяем КАЖДЫЙ элемент
        if (arr[i] === target) return i;
    }
}

// Бинарный поиск O(log n) - зелёная линия
function findBinary(arr, target) {
    let left = 0, right = arr.length - 1;
    while (left <= right) {
        let mid = Math.floor((left + right) / 2);
        if (arr[mid] === target) return mid;
        if (arr[mid] < target) left = mid + 1;
        else right = mid - 1;  // Отсекаем ПОЛОВИНУ на каждом шаге!
    }
}
```

**Сложность** = сколько операций нужно сделать:
- **O(n)** (линейная, красная) = если 1 млн элементов → 1 млн операций
- **O(log n)** (логарифмическая, зелёная) = если 1 млн элементов → ~14 операций

## 4. Почему ln(1000000) ≈ 14 секунд?

Это **аналогия**, не точная формула! Автор просто показывает **пропорцию**:

Без индекса:
```
1 строка = 1 операция
1 000 000 строк = 1 000 000 операций
```

С индексом (B-дерево с ветвлением):
```
1 000 000 строк разделены на уровни дерева
Количество уровней ≈ ln(1 000 000) ≈ 14
Каждый уровень = 1 операция чтения
Итого: ~14 операций вместо миллиона!
```

**Логарифм показывает глубину дерева** = сколько "прыжков" от корня до нужного листа.

## 5. Почему зелёная линия сначала выше красной?

**Отличный вопрос!** Это ключевой момент:

```
При малом количестве строк (слева на графике):
🔴 Красная линия (без индекса): просто читаем 10 строк подряд → быстро
🟢 Зелёная линия (с индексом): нужно:
   1) Прочитать индекс (дополнительная работа)
   2) Найти в индексе ссылку
   3) Прочитать саму строку
   → МЕДЛЕННЕЕ из-за лишних шагов!

При большом количестве строк (справа на графике):
🔴 Красная: читаем 1 000 000 строк → ОЧЕНЬ долго
🟢 Зелёная: 14 операций в индексе → быстро, несмотря на накладные расходы
```

**Вывод из графика**: индексы выгодны только при **достаточно большом** количестве данных. Точка пересечения линий = момент, когда индекс начинает окупаться.

Поэтому в задании написано:
> "иногда приходится явно отключать последовательное сканирование" (`SET enable_seqscan = OFF`)

PostgreSQL **сама решает**, что быстрее. Если данных мало — игнорирует индекс и использует Sequential Scan (красная линия).

## 6. Как индексы связаны с логарифмами?

**B-дерево** устроено так, что каждый узел имеет несколько "детей" (например, 100):

```
Уровень 0 (корень): 1 узел
Уровень 1: 100 узлов (1 × 100)
Уровень 2: 10 000 узлов (100 × 100)
Уровень 3: 1 000 000 узлов (100 × 100 × 100)
```

Чтобы найти нужную строку среди 1 млн:
- Спускаемся на **3 уровня вниз** (а не проходим все 1 млн строк)
- Количество уровней = log₁₀₀(1 000 000) ≈ 3
- Или в натуральном логарифме: ln(1 000 000) / ln(100) ≈ 3

**Математика**: количество шагов = высота дерева = O(log N)
